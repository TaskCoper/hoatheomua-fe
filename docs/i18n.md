# I18n trong dự án

Tài liệu này giải thích cách dự án đang làm đa ngôn ngữ bằng `next-intl`.

## Cách URL hoạt động

Dự án có 2 ngôn ngữ:

- `vi`: tiếng Việt
- `en`: tiếng Anh

Tiếng Việt là ngôn ngữ mặc định.

```txt
/      -> tiếng Việt
/en    -> tiếng Anh
/vi    -> không cần dùng, sẽ về /
```

Trong `lib/i18n/routing.ts`, dự án đang dùng:

```ts
localePrefix: 'as-needed'
localeDetection: false
```

Ý nghĩa:

- `localePrefix: 'as-needed'`: ngôn ngữ mặc định không cần hiện trên URL.
- `localeDetection: false`: khi vào `/`, app luôn dùng tiếng Việt, không tự đổi theo trình duyệt hoặc cookie.

## Các file chính

### `lib/i18n/routing.ts`

Đây là file cấu hình ngôn ngữ chính.

File này khai báo:

- dự án có những ngôn ngữ nào
- ngôn ngữ mặc định là gì
- URL có cần thêm `/en`, `/vi` hay không

Hiện tại:

```ts
locales: ['vi', 'en']
defaultLocale: 'vi'
```

### `proxy.ts`

Đây là middleware của `next-intl`.

Nó chạy trước khi request vào page. Nhiệm vụ của nó là:

- đọc locale từ URL
- xử lý `/`, `/en`, `/vi`
- bỏ qua API, file tĩnh, `_next`

Ví dụ:

- người dùng vào `/en` thì app dùng tiếng Anh
- người dùng vào `/` thì app dùng tiếng Việt

### `next.config.ts`

File này bật plugin của `next-intl`.

Nó trỏ tới file:

```ts
./lib/i18n/request.ts
```

Nhờ vậy `next-intl` biết cách load file dịch cho từng request.

### `lib/i18n/request.ts`

File này load nội dung dịch theo locale hiện tại.

Ví dụ:

- locale là `vi` thì load `lib/i18n/messages/vi.json`
- locale là `en` thì load `lib/i18n/messages/en.json`

Nếu locale không hợp lệ, app sẽ dùng locale mặc định là `vi`.

### `app/[locale]/layout.tsx`

Đây là layout chính cho các route có ngôn ngữ.

File này làm các việc:

- kiểm tra locale có hợp lệ không
- nếu locale sai thì trả về `notFound()`
- set `<html lang="...">`
- bọc app bằng `NextIntlClientProvider`
- bọc app bằng `ReactQueryProvider`

Tất cả page có dịch nên nằm trong thư mục:

```txt
app/[locale]/
```

### `app/[locale]/page.tsx`

Đây là trang home.

Trang này lấy text bằng:

```ts
const { t } = useTranslation()
```

Sau đó dùng:

```tsx
return <Button>{t('home.cta')}</Button>
```

Key `home.cta` sẽ được lấy từ file JSON của ngôn ngữ hiện tại.

### `lib/i18n/messages/en.json`

Đây là file dịch tiếng Anh.

Ví dụ:

```json
{
  "home": {
    "cta": "Click me"
  }
}
```

### `lib/i18n/messages/vi.json`

Đây là file dịch tiếng Việt.

Ví dụ:

```json
{
  "home": {
    "cta": "Bấm vào đây"
  }
}
```

Hai file `en.json` và `vi.json` nên luôn có cùng cấu trúc key.

Đúng:

```txt
en.json có home.cta
vi.json cũng có home.cta
```

Không nên:

```txt
en.json có home.cta
vi.json thiếu home.cta
```

### `lib/i18n/dictionary-provider.tsx`

File này tạo wrapper đơn giản để dùng dịch trong component.

Nó export:

```ts
useTranslation()
useLocale()
```

Dùng trong component:

```tsx
const { t, locale } = useTranslation()

return <button>{t('home.cta')}</button>
```

`locale` là ngôn ngữ hiện tại, ví dụ `vi` hoặc `en`.

### `lib/i18n/types.ts`

File này tạo type cho translation key.

Nó đọc cấu trúc từ `en.json`, rồi tạo type như:

```ts
home.cta
common.dialog.close
dataTable.table.noResults
```

Mục đích là giảm lỗi gõ sai key.

### `lib/i18n/navigation.ts`

File này export các helper navigation của `next-intl`.

Nên dùng các helper này khi cần link hoặc redirect trong app:

```ts
Link
redirect
usePathname
useRouter
getPathname
```

Lý do: các helper này hiểu locale, nên URL sẽ đúng hơn khi đổi ngôn ngữ.

### `scripts/i18n-check.mjs`

Đây là script kiểm tra file dịch.

Nó kiểm tra:

- thiếu key
- dư key
- sai biến trong câu dịch, ví dụ `{count}`
- source code dùng key không tồn tại

Chạy bằng:

```bash
pnpm i18n:verify
```

## Các lệnh i18n

Các lệnh này nằm trong `package.json`.

### `pnpm i18n:lint`

Lệnh này kiểm tra các file dịch.

Nó kiểm tra:

- locale khác có thiếu key so với file chính không
- locale khác có dư key không
- biến trong câu dịch có giống nhau không
- giá trị dịch có bị rỗng không

Ví dụ câu dịch có biến:

```json
{
  "rowsSelected": "{selected} of {total} rows"
}
```

Nếu tiếng Anh có `{selected}` và `{total}`, thì tiếng Việt cũng phải có đủ 2 biến này.

Chạy:

```bash
pnpm i18n:lint
```

Nên dùng khi vừa sửa file JSON dịch.

### `pnpm i18n:check`

Lệnh này kiểm tra key được dùng trong source code.

Nó tìm các key như:

```tsx
t('home.cta')
```

Sau đó kiểm tra key đó có tồn tại trong file dịch chính không.

Chạy:

```bash
pnpm i18n:check
```

Nên dùng khi vừa sửa component có dùng `t(...)`.

### `pnpm i18n:verify`

Lệnh này chạy cả 2 lệnh:

```bash
pnpm i18n:lint
pnpm i18n:check
```

Trong `package.json`, nó đang là:

```json
{
  "i18n:verify": "pnpm run i18n:lint && pnpm run i18n:check"
}
```

Chạy:

```bash
pnpm i18n:verify
```

Nên dùng trước khi commit code có thay đổi i18n.

### `pnpm i18n:unused`

Lệnh này tìm key dịch không còn được dùng trong source code.

Chạy:

```bash
pnpm i18n:unused
```

Nếu có key không dùng, lệnh sẽ in danh sách key đó ra terminal.

Lưu ý: lệnh này có thể không chắc chắn 100% nếu code dùng key động.

Ví dụ key động:

```tsx
t(`dataTable.${type}`)
```

Vì vậy trước khi xóa key, nên kiểm tra lại.

### `pnpm i18n:unused:fix`

Lệnh này cũng tìm key không dùng, nhưng sẽ tự xóa key đó khỏi tất cả file locale.

Chạy:

```bash
pnpm i18n:unused:fix
```

Cẩn thận khi dùng lệnh này.

Nên chạy `pnpm i18n:unused` trước, đọc danh sách key, rồi mới chạy `pnpm i18n:unused:fix`.

### `pnpm check`

Lệnh này không chỉ dành riêng cho i18n, nhưng có chạy i18n bên trong.

Trong `package.json`, nó đang là:

```json
{
  "check": "pnpm run lint && pnpm run i18n:verify && pnpm run typecheck"
}
```

Nó chạy:

- lint code
- kiểm tra i18n
- kiểm tra TypeScript

Chạy:

```bash
pnpm check
```

Nên dùng trước khi tạo pull request hoặc trước khi merge code.

## Cách thêm text mới

Ví dụ cần thêm title cho home.

Thêm vào `lib/i18n/messages/en.json`:

```json
{
  "home": {
    "title": "Welcome"
  }
}
```

Thêm vào `lib/i18n/messages/vi.json`:

```json
{
  "home": {
    "title": "Chào mừng"
  }
}
```

Dùng trong component:

```tsx
const { t } = useTranslation()

return <h1>{t('home.title')}</h1>
```

Sau đó chạy:

```bash
pnpm i18n:verify
```

## Cách thêm ngôn ngữ mới

Ví dụ thêm tiếng Nhật `ja`.

Sửa `lib/i18n/routing.ts`:

```ts
locales: ['vi', 'en', 'ja']
```

Tạo file:

```txt
lib/i18n/messages/ja.json
```

File `ja.json` phải có cùng key với `en.json` và `vi.json`.

Sau đó chạy:

```bash
pnpm i18n:verify
```

## Quy tắc chính:

- `/` là tiếng Việt
- `/en` là tiếng Anh
- text dịch nằm trong `lib/i18n/messages`
- khi thêm key mới, thêm vào tất cả file ngôn ngữ
- chạy `pnpm i18n:verify` để kiểm tra
